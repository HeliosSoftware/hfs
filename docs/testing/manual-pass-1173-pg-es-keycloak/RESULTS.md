So the issue's question "what happens to the Import page when the outbound token expires" no longer applies in the issue's environment: the page is closed before the token matters.     **Root cause (code reading):** `PostgresBackend::init_schema` builds the Patient-reference GIN index only when search is not offloaded (`init_schema_with_patient_export_index(!self.config.search_offloaded)`, `crates/persistence/src/backends/postgres/backend.rs:795`), and `has_patient_export_index()` returns false whenever `search_offloaded` (`backend.rs:825`); the rationale is in `schema.rs:46-48` (*"Audit-only and search-offloaded PostgreSQL instances do not need this large index"*). But `$export` on `pg-es` still reads from PostgreSQL, so `fetch_patient_compartment_batch` (`crates/persistence/src/backends/postgres/bulk_export.rs:1364`) takes the non-indexed branch: `WHERE tenant_id=$1 AND resource_type=$2 AND is_deleted=FALSE AND EXISTS (SELECT 1 FROM jsonb_path_query(data, '$.**.reference') …) ORDER BY last_updated, id LIMIT 1001` (`bulk_export.rs:1430-1488`). With 165 matches among 7,699,987 Observations the planner walks every row of the type evaluating the JSON path, exceeding the 30 s default `HFS_PG_STATEMENT_TIMEOUT_MS` (`backend.rs:291`); the error surfaces as `Failed to query compartment: db error` (`bulk_export.rs:1500`) and the client only sees *"internal storage error"*. Timeline: kick-off 16:40:05Z, failure 16:40:45Z — consistent with Patient and Condition finishing and the Observation batch timing out. The same path is used by Group export of a resource type with a large table (5.3 only exported Patient + Condition, 476k rows, and passed).
    **Fix directions for the issue:** build the GIN index on `pg-es` too (it was 57 MB and ~6 min to build on the full corpus per PR #1594), or resolve compartment candidates through Elasticsearch when search is offloaded; and surface the underlying cause (statement timeout) instead of a bare *internal storage error*. Workaround: raise `HFS_PG_STATEMENT_TIMEOUT_MS` (the #1582 run used 600000 and took 46 s).
