Same-URL GET means the nojs fallback stays coherent (a hard nav to /translate?direction=reverse still lands the right form). `hx-params="none"` is critical: without it, htmx serialises the trigger radio's own form value (`name="direction"`, currently- checked `value="reverse"`) onto the GET URL. Because the URL already carries the literal `?direction=reverse` from `hx-get`, the wire ends up as `?direction=reverse&direction=reverse`, which axum's `Query` (serde_urlencoded's derived Deserialize) rejects with HTTP 400 on the duplicate scalar field. htmx's default 4xx handler is `swap: false`, so the reverse fieldset never lands in the DOM and Playwright times out looking for `Target code`. `hx-params="none"` short-circuits htmx's FormData collection for these two triggers so the URL is emitted verbatim. Without it htmx appends the form's own fields, producing a duplicate scalar that `Query` rejects with HTTP 400 — and since htmx's default 4xx handler is `swap: false`, the failure is silent. `hx-select="#hts-workbench-input"` is equally critical: the GET handler (`translate_input` in crates/hts-ui/src/concept_maps.rs) always renders the full `DetailPageTemplate` (extends `layouts/base.html`) so the nojs hard-nav fallback keeps working. Without `hx-select`, htmx would swap the entire response body into the form's outerHTML slot, nesting a second `#hts-cm-detail-region` / `#hts-cm-workbench` / `#hts-workbench-input` / `#hts-workbench-result` under the workbench and leaving the original `#hts-workbench-result` sibling untouched. Subsequent Playwright `page.locator("#hts-workbench-result")` calls trip strict-mode with two matches; htmx also picks the first-in-DOM (nested) result region on the next POST swap, so the operator's match table ends up hidden below a stale empty-state block.
