{#- Home cards fragment (design doc §7.1). Rendered once on hard navigation as part of `pages/home.html`, and again on every 15 s htmx refresh via `GET /ui/hts/home/cards`. Same markup either way — the outer `#hts-home-cards` region is swapped wholesale, so a partial failure never blanks the healthy tiles. Style: reuse the HFS `.stat-grid` / `.card.stat` primitives from `crates/ui/assets/app.css` so the terminology home page reads with the same visual grammar as the FHIR-server home. The fragment is selected in tests by its `#hts-home-cards` id, not by a class — every class here has a real rule in app.css. (The quick-links strip was removed on 2026-08-27; `.hts-quick-strip` / `.hts-quick-links` went with it, and the degraded banner moved to the shared `.notice.notice--warn` primitive.) The Requests tile and its latency sub-line are fed by `HomeCards::fetch()` scraping `/metrics` (Prometheus text). Both fields are `Option`, so a fetch or parse failure falls back to an em-dash without breaking the surrounding cards — the design's fail-open invariant (§7 degraded contract). The 15 s poll lives on THIS element, not on a wrapper around it, and carries no `hx-target`: htmx defaults the target to the element itself, and `hx-swap="outerHTML"` therefore replaces the element *including this refreshed `hx-get`*. Because `refresh_href()` embeds the current `?window=&series=`, the chart selection is self-perpetuating. The previous shape — an outer, never-swapped wrapper carrying `hx-target="#hts-home-cards"` — froze its URL at first paint, so any selection would have been reverted by the next tick. Same pattern as `#hts-batch-progress`. -#}
