{#- Step 3 — "Result" — of the V3 stepped Import layout (design doc §7.7). This partial renders the *contents* of the `#hts-import-status` card (`.card-head` + `.panel`), not a wrapper: `#hts-import-status` is itself the htmx swap target (`hx-swap="innerHTML"`) and must stay a `.card` sibling of steps 1 and 2 so `.content > .card ~ .card` keeps spacing it. The four `StatusView` variants are visually distinct through shared HFS primitives only — no `hts-import-status--*` modifiers, which never had a CSS rule and made success and partial-success indistinguishable: success → `.notice` (muted line, no chrome) + `.tag.tag--matched` partial → `.notice.notice--warn` + `.tag.tag--muted` rejected → `.notice.notice--warn` + `.tag.tag--excluded` too-large → `.notice.notice--warn` + `.tag.tag--excluded` There is deliberately no `.notice--ok`: app.css does not define one and this partial does not invent CSS. The success state reads as a muted line plus a green tag. `data-import-status` on the panel is the stable machine hook the Rust ring keys off of (it replaces the old class markers and carries no styling). When the upstream round-trip failed at the transport layer (5xx / connect / timeout) the shared `hts-degraded.html` banner renders inside the panel instead of a variant banner. Note on `.field` wrappers below: `.field` is used purely as the shared "block with bottom margin" primitive (app.css: `display:block; margin-bottom:14px`) so the counts table and the disclosures are not flush against each other. No new CSS is introduced. -#}
