{% import "partials/sql_parameter_fields.html" as param_fields %} {# The Parameters card (#841, SQL Query only — `sql-library.html` never includes this for SQL Views, since `LibraryKind::declares_parameters` is `false` there): one `.field` per `Library.parameter[use=in]` declaration for this run's own values (`sql_parameter_fields.html`, `prefix="param"`, `form="lib-editor-form"` — the same shared partial #837's SQL Export builder uses), the `:name` placeholders the SQL uses but does not declare as one-click *Declare* hints, and the *Add parameter* panel that writes a fresh declaration into the Details document. Rendered three ways, all built by `crate::build_params_card` from one `crate::ParamsAnalysis` so none of them can disagree about what is declared or what the signature is: - The page's own inline render (`oob: false`, `data_document: None`) — part of the normal document flow, nothing to swap into. - The `/run` fragment's OOB companion (`oob: true`) — only when the freshly computed `signature` differs from what the browser posted (`crate::sql_library_run`'s own comparison); typing a parameter value never changes the signature, so the card never re-renders — and never loses focus — just from that (#841's NF2). - The `document` endpoint's own `HX-Request` response (`oob: false` — the request's own `hx-target="#lib-params"` swaps this element directly, no OOB needed): `data_document` carries the updated Details JSON on a successful `add-parameter`, which `sql-library-panels.js` applies through the JSON editor's own undo-tracked host (`host.setDoc`) and then strips off this element. The card itself carries the live-run wiring (#841): every value field's own `input` event bubbles up to `hx-trigger="input delay:500ms"` here, `hx-include="#lib-editor-form"` gathers the rest of the document (Details JSON, SQL, every other declared value) the same way that form's own JSON/SQL panes already do, and the response lands in `#run-notice` exactly like every other edit on this page. `Add parameter`/`Declare` are real `type="submit"` buttons — `form="lib-editor-form"` and `formaction="{{ document_href }}"` — so both work with no JavaScript at all (#841's NF3): a plain submit posts the whole document to the `document` endpoint, which re-renders the entire page with the mutation applied and nothing saved. With JavaScript, each button's own `hx-post`/`hx-target="#lib-params"`/`hx-swap="outerHTML"` intercepts that same submit and swaps only this card. A *Declare :name* button carries no separate `op` field of its own — its `name="declare_param" value="{{ hint }}"` pair alone is what `crate::sql_library_document` reads as "add this name, type string" (#841); the *Add parameter* panel's own button carries `name="op" value="add-parameter"` instead, alongside the panel's own `param_name`/`param_type` fields. #}
