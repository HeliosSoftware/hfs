# M1 - First-Class Mode Wiring (`s3-elasticsearch`)

## Goal
Make `s3-elasticsearch` selectable and bootable as a first-class backend mode using existing `CompositeStorage` search offloading patterns.

## Implemented Tasks

1. Add backend mode parsing/display aliases in `helios-rest`.
- Files:
  - `crates/rest/src/config.rs`
- Purpose:
  - Ensure `HFS_STORAGE_BACKEND=s3-elasticsearch` and alias `s3-es` parse consistently with existing `*-elasticsearch` modes.
- Tests:
  - Added/updated parse + display tests in `crates/rest/src/config.rs`.

2. Add HFS startup path for S3 primary + ES search secondary.
- Files:
  - `crates/hfs/src/main.rs`
- Purpose:
  - Add `start_s3_elasticsearch()` to instantiate:
    - primary: `S3Backend`
    - search secondary: `ElasticsearchBackend`
    - composite config:
      - `.primary("s3", BackendKind::S3)`
      - `.search_backend("es", BackendKind::Elasticsearch)`
      - `.sync_mode(SyncMode::Synchronous)`

3. Add shared ES search registry bootstrap.
- Files:
  - `crates/hfs/src/main.rs`
  - `crates/hfs/Cargo.toml` (adds `parking_lot` for shared `RwLock`)
- Purpose:
  - Load embedded/spec/custom search parameters once and pass shared registry into Elasticsearch for parity with other composite modes.

4. Expand S3 env parsing used in startup.
- Files:
  - `crates/hfs/src/main.rs`
- Purpose:
  - Parse tenancy mode, bucket map, endpoint options, and validation flags for both `s3` and `s3-elasticsearch`.
- Key env vars:
  - `HFS_S3_TENANCY_MODE`
  - `HFS_S3_BUCKET`
  - `HFS_S3_TENANT_BUCKET_MAP`
  - `HFS_S3_DEFAULT_SYSTEM_BUCKET`
  - `HFS_S3_REGION`
  - `HFS_S3_PREFIX`
  - `HFS_S3_ENDPOINT_URL`
  - `HFS_S3_FORCE_PATH_STYLE`
  - `HFS_S3_ALLOW_HTTP`
  - `HFS_S3_VALIDATE_BUCKETS`

5. Add startup reindex env parsing.
- Files:
  - `crates/hfs/src/main.rs`
- Purpose:
  - Parse `HFS_S3_ES_REINDEX_ON_STARTUP` and related options for operator-triggered drift repair.

## Validation
- `cargo test -p helios-rest`
- `cargo test -p helios-hfs --features s3,elasticsearch`
