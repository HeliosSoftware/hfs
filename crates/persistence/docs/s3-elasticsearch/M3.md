# M3 - Reindex/Repair + End-to-End Validation

## Goal
Provide operator-grade drift repair and end-to-end test coverage for MinIO + Elasticsearch.

## Implemented Tasks

1. Add S3 -> Elasticsearch reindex utility.
- Files:
  - `crates/persistence/src/backends/s3/reindex_es.rs`
  - `crates/persistence/src/backends/s3/mod.rs`
- Purpose:
  - Scan S3 current objects, replay index updates/deletes into ES, support batching and optional resource-type filters.
  - Support `clear_existing` behavior for targeted rebuilds.
- Tests:
  - key parsing/unit coverage in `reindex_es.rs`

2. Add startup trigger wiring for reindex.
- Files:
  - `crates/hfs/src/main.rs`
- Purpose:
  - Parse startup env trigger/options and invoke reindex during `s3-elasticsearch` startup when requested.

3. Add MinIO + Elasticsearch integration test suite (testcontainers).
- Files:
  - `crates/persistence/tests/minio_s3_elasticsearch_tests.rs`
- Gating:
  - `RUN_MINIO_S3_ES_TESTS=1`
- Scenarios:
  - CRUD roundtrip with canonical reads from S3
  - Search served by ES after write-through
  - Delete propagation behavior
  - Tenant isolation
  - Reindex rebuild after ES state loss

4. Stabilize timing-sensitive assertions.
- Files:
  - `crates/persistence/tests/minio_s3_elasticsearch_tests.rs`
- Purpose:
  - Use explicit ES refresh and retry/backoff helpers to reduce nondeterminism from refresh lag.

## Validation
- `cargo test -p helios-persistence --features s3,elasticsearch --test minio_s3_elasticsearch_tests`
- Suite returns early unless `RUN_MINIO_S3_ES_TESTS=1` is set.
